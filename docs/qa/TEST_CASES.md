# 테스트 케이스

StayOps를 실제 사용자 관점에서 확인하는 테스트 케이스 목록입니다. 각 케이스는 **운영 테스트**(실행 중인 데모 서비스에 대해 브라우저·API로 수행, `apps/web/ops/ops.spec.ts`)로 자동 실행되며, 같은 규칙을 더 작은 단위로 확인하는 자동 테스트도 함께 적었습니다.

- 실행 결과: [OPERATIONAL_TEST_REPORT.md](OPERATIONAL_TEST_REPORT.md)
- 대상 환경: 데모 서비스(웹 + API `demo` profile + PostgreSQL), 데모 데이터를 새로 만든 직후 상태
- 데모 직원: 운영 관리자 MGR-01 · 프런트 FD-01 · 하우스키핑 HK-01, HK-02 · 근무 종료 하우스키핑 HK-03 · 검사 IN-01

## 실행 방법

```bash
# 1) 깨끗한 데모 데이터로 API를 띄운다 (데모 데이터를 지금 시각 기준으로 새로 만든다)
cd apps/api && ./gradlew bootRun --args='--spring.profiles.active=demo --stayops.demo.force-refresh-on-startup=true'
# 2) 웹을 띄운다
cd apps/web && pnpm dev --port 3100     # API가 8080이 아니면 NEXT_PUBLIC_STAYOPS_API_BASE_URL 지정
# 3) 운영 테스트 실행 — 케이스별 화면 캡처는 apps/web/ops-results/evidence/
cd apps/web && STAYOPS_OPS_WEB=http://localhost:3100 STAYOPS_OPS_API=http://localhost:8080 pnpm test:ops
```

케이스는 데모 데이터를 순서대로 바꾸므로 한 번에 처음부터 끝까지 실행합니다. 다시 실행하려면 1)부터 반복합니다.

## 케이스 상세

### TC-A01 데모 사용자 선택 화면
- **사전 조건:** 로그인하지 않은 상태
- **절차:** `/` 접속
- **기대 결과:** 직원 6명(근무 종료 HK-03 포함)이 보인다. '데모 데이터' 표시가 있고 '합성'이라는 표현은 없다. '사용 설명서' 링크가 있다.
- **함께 확인하는 자동 테스트:** E2E `a11y.spec.ts`(접근성)

### TC-A02 역할별 메뉴
- **절차:** MGR-01, FD-01, HK-01, IN-01로 차례로 바꿔 상단 메뉴 확인
- **기대 결과:** 관리자·프런트는 대시보드·객실·작업·예약·시뮬레이션 5개, 하우스키핑·검사는 객실·작업 2개

### TC-A03 하우스키핑은 자기 작업만 봄
- **절차:** HK-01로 작업 화면 열기
- **기대 결과:** '본인에게 배정된 작업만 표시합니다' 안내, 보이는 모든 작업 카드의 담당이 HK-01
- **함께 확인:** API `QueryApiTests`(역할별 조회 범위)

### TC-T01 근무 외 직원 배정 거부
- **절차:** MGR-01 → 작업 → 202호 체크아웃 청소 [배정] → HK-03 선택 → 제출
- **기대 결과:** 대화상자 안에 '선택한 직원이 작업 예정 시각에 근무하지 않습니다'와 추적 ID. 배정되지 않음
- **함께 확인:** API `TaskLifecycleTests`(SHIFT_CONFLICT)

### TC-F01 핵심 흐름 (202호)
- **사전 조건:** 202호 체크아웃 청소가 담당자 없이 대기
- **절차:**
  1. MGR-01: 청소를 HK-02에게 배정
  2. HK-02: 시작 → 차단 등록(린넨, 15분) → 해제 → 완료
  3. MGR-01: 자동 생성된 검사를 IN-01에게 배정
  4. IN-01: 시작 → 검사 결과 '실패'를 사유 없이 제출(거부 확인) → 사유 입력 후 제출
  5. MGR-01: 자동 생성된 재청소(생성 원인 '검사 실패')를 HK-02에게 배정 → HK-02 시작·완료
  6. MGR-01: 재검사 배정 → IN-01 통과
  7. FD-01: 202호 상세에서 운영 상태 '준비 완료'와 타임라인 확인 → 예약에서 체크인
- **기대 결과:** 각 단계에서 작업 상태가 바뀌고, 실패 사유 없이는 제출되지 않으며, 마지막에 '202호 체크인했습니다'
- **함께 확인:** E2E `workflow.spec.ts`, API `RoomWorkflowTests`·`TaskLifecycleTests`·무작위 시퀀스 불변식 테스트

### TC-R01 체크인 가능 여부 사전 안내
- **절차:** FD-01 → 예약
- **기대 결과:** 청소 중인 204호는 '객실 청소 중' 표시, 체크인 버튼 꺼짐, '청소 완료와 검사가 남았습니다' 안내. 준비 완료인 101호는 체크인 성공
- **함께 확인:** 단위 `reservations.test.tsx`, API `QueryApiTests`(예약에 객실 단계 포함)

### TC-R02 판매 중단 객실
- **절차:** FD-01 → 102호 체크인 버튼 확인 → MGR-01 → 102호 상세 [판매 재개] → 사유 없이 제출(거부 확인) → 사유 입력 후 제출 → FD-01 체크인
- **기대 결과:** 처음엔 버튼 꺼짐과 '판매 중단된 객실이라 체크인할 수 없습니다'. 사유 필수. 재개 후 판매 상태 '판매 가능', 체크인 성공
- **함께 확인:** E2E `exceptions.spec.ts`, API `RoomWorkflowTests`

### TC-R03 투숙 중 청소 중 체크아웃
- **절차:** MGR-01이 104호 투숙 중 청소를 HK-01에게 배정 → HK-01 시작 → FD-01 예약 화면 → 체크아웃 시도 → HK-01 완료 → 다시 체크아웃
- **기대 결과:** 누르기 전 '지금은 체크아웃이 거부됩니다' 안내. 누르면 '시작된 투숙 중 청소가 있어 체크아웃할 수 없습니다'와 해결 방법. 청소 완료 후 체크아웃 성공
- **함께 확인:** E2E `exceptions.spec.ts`, API `StayCommandTests`(8가지 상태 조합)

### TC-T02 작업 취소 후 재청소 만들기
- **절차:** MGR-01 → 303호 재청소 [작업 취소](사유 입력) → 303호 상세 → [재청소 작업 만들기](사유 입력)
- **기대 결과:** 취소 후 업무 단계 '청소 필요', 진행 중인 작업 없음 → 만들기 후 진행 중인 작업에 재청소
- **함께 확인:** API `RoomWorkflowTests`(재정비)

### TC-D01 준비 예측 표시
- **절차:** MGR-01 대시보드
- **기대 결과:** '준비 예측 — 손님 도착 전에 객실이 준비될까요?' 제목과 설명. 등급이 늦을 예정·예측 불가·빠듯함·여유 있음·준비 완료로 표시. 304호 원인 '차단 해제 예상 시각 없음', 201호 원인 '예정 체크아웃이 지났지만 아직 투숙 중'. '준비 위험'·'판정 불가' 표현 없음
- **함께 확인:** API `ReadinessCalculatorTests`·`ReadinessApiTests`

### TC-S01 시뮬레이션
- **사전 조건:** `tools/simulator`에서 `uv run stayops-simulator generate --seed 42 --out output/dataset-42.json`
- **절차:** MGR-01 → 시뮬레이션 → 파일 업로드 → 대안 A·B 선택 → 실행 → FD-01로 같은 화면
- **기대 결과:** 데이터셋 '데모 호텔 A'. 정시 준비율이 [DATASET.md](../simulation/DATASET.md) 기록값과 같다(기준 81.5% · 대안 A 96.3%). 프런트에는 '정책 비교 실행' 영역이 없다
- **함께 확인:** API `SimulationEngineTests`·`SimulationApiTests`, Python 계약 fixture

### TC-U01 사용 설명서
- **절차:** `/guide` → 탭 이동 → `/guide#readiness`로 바로 열기 → '문제 해결' 탭
- **기대 결과:** 탭 5개(빠른 시작·역할별·상태별·메뉴별·문제 해결). 선택한 탭이 주소에 남음. 섹션 링크로 들어오면 그 섹션의 탭이 열림. '막혔을 때 해결 방법' 제목. '합성'·'자주 만나는'·'준비 위험'·'판정 불가' 표현 없음
- **함께 확인:** 단위 `guide.test.tsx`(문서 동기화·없는 라벨 사용 금지)

### TC-U03 라이트·다크 모드
- **절차:** 라이트, 다크 각각으로 대시보드·객실·작업·예약·시뮬레이션·사용 설명서 열기
- **기대 결과:** 모든 화면 axe 심각(serious·critical) 위반 0, 화면 캡처로 대비 확인
- **함께 확인:** E2E `a11y.spec.ts`(배경 밝기 확인 포함)

### TC-X01 API 경계
- **절차:** 실행 중인 API에 직접 요청
- **기대 결과:** 요청자 헤더 없음 401 `UNAUTHENTICATED` · 하우스키핑이 예약 목록 403 · 없는 호텔 404 · Idempotency-Key 없는 명령 400 · 6MB 본문 413 `PAYLOAD_TOO_LARGE` · 같은 키로 두 번 보내면 두 번째는 `Idempotency-Replayed: true`와 같은 응답
- **함께 확인:** API `CommandInfrastructureTests`·`RequestSizeLimitTests`

### TC-M01 데모 데이터 매일 새로 만들기
- **확인 방법:** 자동 테스트 `DemoDataRefresherTests` + 운영 확인(API 시작 로그와 DB의 데모 호텔 생성 시각)
- **기대 결과:** 오늘 새벽 4시(한국 시간) 이후에 만든 데이터는 그대로 둔다. 그 이전 데이터는 지우고 지금 시각 기준으로 다시 만든다. 예전 이름의 데모 호텔도 정리된다. **다른 호텔의 데이터는 바뀌지 않는다.**
