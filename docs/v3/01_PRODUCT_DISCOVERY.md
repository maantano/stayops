# StayOps — 문제 정의·리서치·가설 검증

> 기준일: 2026-11-04  
> 상태: 공개 자료 기반 데스크 리서치 및 제품 가설  
> 제약: 운영자 인터뷰 및 내부 운영 데이터는 확보하지 못했다. 현장 문제 빈도·심각도·지불 의사·실제 성과는 입증되지 않았다.

## 1. 프로젝트 개요

- 프로젝트명: **StayOps — Room Readiness & Operations** (가칭)
- 도메인: 호텔·레지던스 객실 준비 및 하우스키핑 운영
- 맥락: 핸디즈 / 어반스테이 소프트웨어 엔지니어 포지션
- 구현 담당: Claude Code
- 제품·리서치·설계: 사용자와 ChatGPT 협업
- 제품 형태: 객실·예약·청소·검사·작업자 정보를 연결해 준비 위험의 근거를 설명하고 운영 대안을 비교하는 도구

### 제품 가설
객실·예약·작업·작업자 정보를 연결하고 객실 준비 위험의 원인을 설명하며 운영 조건 변경 결과를 시뮬레이션할 수 있다면 객실 준비 관련 의사결정을 더 빠르고 일관되게 수행할 수 있을 것이다.

이는 검증 전 `HYPOTHESIS`다.

## 2. 사업 맥락

핸디즈 공개 사업 소개에는 숙박 자산 위탁 운영·관리(Plott Stay), 가격 운영, OTA 채널 운영 자동화, 다국어 고객 서비스, 자산 생애주기 관리(Plott AMC) 등이 소개되어 있다.

- `EVIDENCE`: 공개 사업 소개에서 위 사업 영역을 확인할 수 있다.
- `INTERPRETATION`: 숙박 운영은 예약 화면뿐 아니라 객실·시설·고객 응대·가격·정산 등 여러 업무가 연결되는 영역이다.
- `OPEN`: 내부 시스템의 구체적 구조, 현장 업무 방식, 운영상의 문제는 공개 자료만으로 알 수 없다.

출처: https://handys.co.kr/business

## 3. 문제 후보와 선택 범위

문제 후보(`HYPOTHESIS`):
1. 객실 준비 지연을 늦게 인지할 수 있다.
2. 지연 원인이 청소·검사·린넨·비품·시설 이슈 중 무엇인지 파악하기 어려울 수 있다.
3. 우선순위가 체크인 예정 시각, 작업 소요 시간, blocker, 작업자 가용성을 함께 반영하지 못할 수 있다.
4. 작업자별 업무량과 근무시간을 고려한 배정이 어려울 수 있다.
5. 운영 조건 변경 결과를 사전에 비교하기 어려울 수 있다.

선택 범위: **객실 준비 위험의 원인 설명 + 작업 우선순위 지원 + 운영 조건 변경 시뮬레이션**.

기본 객실 상태판과 단순 작업 배정은 기존 PMS/하우스키핑 제품에도 존재하므로 그것만으로 차별성을 주장하지 않는다. 차별화 가설은 위험 계산의 입력·원인을 투명하게 보여주고 예외 흐름을 명시하며 재현 가능한 운영 시나리오를 비교하는 데 둔다.

## 4. 공개 리서치

### 4.1 청소 시간의 변동 요인
**Hotel room cleaning: Time study and analysis of influential variables in a Spanish hotel**
- 스페인 4성급 호텔에서 객실 청소 시간을 측정하고 영향 변수를 분석했다.
- 작업 관련 변수가 총 청소 시간에 통계적으로 유의한 영향을 미쳤다고 보고한다.
- 객실 청소 시간을 하나의 고정 상수로만 취급하지 않는 설계의 참고 근거다.
- 한계: 특정 호텔 결과를 업계 평균이나 어반스테이 실측값으로 일반화하지 않는다.
출처: https://www.jiem.org/index.php/jiem/article/view/3441

### 4.2 린넨 대기 및 객실·고객 유형
**Employee Productivity of Hotel Room Attendants: An Input–Output Perspective**
- 홍콩 호텔 객실 22개 청소 과정과 객실 정비 담당자 18명을 조사했다.
- 린넨 공급 대기와 객실/고객 세그먼트별 시간 차이를 다룬다.
- blocker 및 작업별 소요 시간 모델의 참고 근거다.
- 한계: 표본·환경이 제한적이며 수치를 프로젝트 기본값으로 직접 사용하지 않는다.
출처: https://doi.org/10.1080/15256480.2021.1881941

### 4.3 작업자 스케줄과 객실 준비
**Capacity Planning for Resource Turnaround Operations**
- 대형 도심 호텔 실제 데이터를 기반으로 하우스키핑 인력 배치를 연구했다.
- 교대 시작 시각 분산과 객실 준비/고객 대기 문제를 분석한다.
- 근무시간과 작업량을 함께 고려하는 시뮬레이션의 참고 근거다.
- 한계: 논문 환경의 실험 결과를 StayOps 성과로 인용하지 않는다.
출처: https://doi.org/10.1287/msom.2025.0395

### 4.4 기존 제품 기능
- Oracle OPERA Cloud는 예약, 객실, 청구, 하우스키핑, 객실 상태, 배정 및 유지보수 요청 등을 소개한다. https://www.oracle.com/hospitality/hotel-property-management/
- Mews Operations는 객실 상태 및 하우스키핑 운영 기능을 문서화한다. https://help.mews.com/s/article/Mews-Operations
- Mews Room Overview는 객실 개요·상태·작업 관련 화면을 설명한다. https://help.mews.com/s/article/mobile-room-overview

기존 제품에 특정 기능이 없다고 단정하지 않는다. 공개 문서에서 확인한 범위와 확인하지 못한 범위를 구분한다.

## 5. 가설과 검증 계획

| ID | 가설 | 검증 방법 | 지표 | 한계 |
|---|---|---|---|---|
| H1 | 준비 위험을 조기에 식별할 수 있다 | 고정 seed 시나리오에서 예측과 실제 완료 비교 | 위험별 지연률, 감지 리드타임, UNKNOWN 비율 | 합성 성능은 현장 정확도 증명이 아님 |

| H3 | 대안 비교가 판단을 지원한다 | 동일 초기 데이터에서 정책만 변경 | 정시 준비율, 평균 지연, 미완료, 작업자 부하 | 현장 최적해가 아님 |
| H4 | 이벤트 이력으로 원인을 재구성할 수 있다 | 이벤트 기반 타임라인 재구성 | 누락·중복 이벤트, 일관성 | 구현 데이터 범위에 한정 |

## 6. 검증 방식 및 인터뷰 제약

운영자 인터뷰는 수행하기 어렵다는 제약을 전제로 한다. 인터뷰를 필수 선행 조건으로 두지 않는다.

대체 검증:
1. 공개 학술 연구와 공식 제품 문서 조사
2. 업무 프로세스 및 상태 전이의 논리 검토
3. 합성 데이터와 고정 seed 시나리오
4. 정상·예외·경계 조건 자동화 테스트
5. 계산 결과와 시뮬레이션 결과의 일관성 검증
6. 비전문가 화면 이해도 점검이 가능하면 수행하되 호텔 운영자 검증으로 표현하지 않음

## 7. 합성 데이터 가정

가상 호텔:
- 객실 80실: Standard 40, Deluxe 24, Suite 12, Family 4
- 하우스키핑 담당자 6명, 검사 담당자 2명
- 기본 checkout 11:00, check-in 15:00
- 시뮬레이션 14일

초기 시간 범위:
- checkout cleaning 30–55분
- stayover cleaning 15–30분
- inspection 5–10분
- 린넨 대기 0–20분
- 시설 blocker 10–60분

모두 `ASSUMPTION`이며 업계 평균/표준/실측치가 아니다. 설정 파일로 분리하고 UI/리포트에 합성 데이터임을 표시한다. seed와 파라미터를 저장한다.

## 8. MVP 범위

포함:
- 운영 대시보드, 객실 목록/상세/타임라인
- 예약 check-in/check-out 명령
- 청소 작업 생성·배정·재배정·시작·차단·해제·완료·취소
- 검사 및 재청소 흐름
- 투숙 중 청소 생성/진행
- 객실 준비 위험 및 원인 설명
- 작업 우선순위·작업자 부하
- 운영 이벤트
- 합성 데이터 생성 및 시나리오 비교

제외:
- 결제/정산, 전체 PMS 대체, 실제 PMS API 연동, 고객 SMS
- 머신러닝 예측, 초기 마이크로서비스
- AI의 운영 명령 자동 실행
- 실운영 인력/객실 배정 최적화 보장

## 9. 내부 평가 지표

포트폴리오 프로젝트의 시뮬레이션 지표이며 사업 성과 KPI가 아니다.
- 정시 준비율 = 준비 대상 중 마감 이전 READY 비율
- 평균 지연 = 지연 객실의 준비 마감 대비 READY 지연 시간 평균
- 위험 감지 리드타임 = 위험 최초 감지와 준비 마감 사이 시간
- UNKNOWN 비율 = 필수 입력 누락으로 판정 불가한 객실 비율
- 작업 완료율 = 완료된 유효 작업 / 유효 작업
- 작업자 부하 = 근무 가능 시간 대비 배정 작업 예상 시간
- 시나리오 차이 = 기준 정책 대비 대안 정책 지표 변화

기간·분모·산식·누락 처리 방식을 함께 표시한다.
