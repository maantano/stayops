## 빠른 시작

_처음 들어왔다면 여기부터 보세요._

<a id="what"></a>

### StayOps는 무엇을 하나요?

손님이 체크아웃하면 객실은 청소와 검사를 거쳐야 다음 손님을 받을 수 있습니다. StayOps는 이 과정에서 지금 어디가 막혀 있는지, 누가 무엇을 해야 하는지, 다음 손님이 오기 전에 준비가 끝날지를 한 화면에서 보여 줍니다.

`투숙 중` (손님이 머무는 중) → `청소 필요` (체크아웃 후 청소 대기) → `청소 중` (하우스키핑이 청소) → `검사 대기` (청소 끝, 검사 대기) → `검사 중` (검사자가 확인) → `준비 완료` (다음 손님 체크인 가능)

<a id="first-steps"></a>

### 처음 사용하기

1. 첫 화면에서 직원을 한 명 고릅니다. 실제 로그인이 아니라, 고른 직원의 역할로 화면을 보는 데모 방식입니다.
2. 처음이라면 **운영 관리자**(MGR-01)로 시작하세요. 모든 메뉴를 볼 수 있습니다.
3. 다른 역할로 바꾸려면 오른쪽 위 [사용자 변경]을 누릅니다. 한 객실의 일을 끝까지 해 보려면 역할을 여러 번 바꿔야 합니다.
4. 언제든 오른쪽 위 [사용법]을 누르면 이 설명서로 돌아옵니다.

> 화면의 모든 데이터는 데모 데이터입니다. 매일 새벽 4시(한국 시간)에 지금 시각 기준으로 새로 만들어지므로, 그 사이에 바꾼 내용은 다음 날 처음 상태로 돌아갑니다.

- 시각은 모두 호텔 시간(한국 시간)으로 보입니다.
- 대시보드와 준비 예측은 30초마다 저절로 새로 고쳐집니다. 다른 역할로 처리한 일도 곧바로 반영됩니다.

<a id="walkthrough"></a>

### 데모로 따라 해 보기

데모 데이터가 새로 만들어졌을 때 각 객실의 상태입니다. 아래 순서대로 해 보면 주요 기능을 모두 써 볼 수 있습니다.

| 객실 | 처음 상태 | 해 볼 것 |
|---|---|---|
| 202호 | `청소 필요` 담당자 없음 | **운영 관리자** 배정 → **하우스키핑** HK-02 시작·완료 → **운영 관리자** 검사 배정 → **검사** 검사(실패도 해 보기) → **프런트** 체크인 |
| 101호 | `준비 완료` | **프런트** 예약 화면에서 바로 [체크인] |
| 203호 | `청소 중` HK-01 담당 | **하우스키핑** HK-01로 바꿔 [차단 등록] → [해제] → [완료] |
| 204호 | `청소 중` 린넨 부족으로 `차단됨` | 대시보드에서 차단 해제 예상 시각이 예측에 반영된 것 확인 → HK-02로 [해제] |
| 301호 / 302호 | `검사 대기` / `검사 중` | **검사** IN-01로 바꿔 검사 시작, [검사 결과 입력] |
| 303호 | 검사 실패 후 재청소 대기 | 작업 카드의 생성 원인 '검사 실패' 확인 → 재청소 배정 |
| 304호 | 방해 금지(DND)로 `차단됨`, 해제 예상 시각 없음 | 준비 예측이 `예측 불가`인 이유 확인 |
| 102호 | `준비 완료`이지만 `판매 중단` | **프런트** 체크인 버튼이 꺼진 이유 확인 → **운영 관리자** 객실 상세에서 [판매 재개] → 체크인 |
| 104호 | `투숙 중`, 투숙 중 청소 요청 있음 | **운영 관리자** 배정 → **하우스키핑** HK-01 시작 → **프런트** 체크아웃 시도(거부와 해결 방법 확인) → HK-01 완료 → 체크아웃 |
| 201호 | 예정 퇴실 시각이 지났는데 아직 투숙 중 | 준비 예측이 `예측 불가`인 이유 확인 → 체크아웃하면 청소가 시작됨 |

## 역할별

_내 역할에서 하루 동안 무엇을 하는지 정리했습니다._

<a id="role-cards"></a>

### 역할별 업무

#### **운영 관리자** MGR-01

- **보이는 메뉴:** 대시보드 · 객실 · 작업 · 예약 · 시뮬레이션
- **하루 흐름:**
  1. 대시보드에서 `늦을 예정`·`예측 불가` 객실 확인
  2. 작업 화면에서 `대기` 작업을 근무 중인 직원에게 [배정]
  3. 청소가 끝나 생긴 검사 작업을 검사자에게 배정
  4. `차단됨` 작업의 원인 해결을 돕고 [해제]
  5. 필요하면 [판매 중단]·[판매 재개], [재청소 작업 만들기]
- **할 수 없는 일:** 직원 대신 작업을 시작·완료하거나 검사 결과를 입력하는 일. 실제 작업은 담당자 본인이 합니다.

#### **프런트** FD-01

- **보이는 메뉴:** 대시보드 · 객실 · 작업 · 예약 · 시뮬레이션(보기만)
- **하루 흐름:**
  1. 대시보드에서 오늘 도착 손님의 객실이 준비될지 확인
  2. 퇴실 손님 [체크아웃] (청소 작업이 자동으로 생김)
  3. 도착 손님 [체크인] (`준비 완료`이고 판매 중일 때만)
  4. 투숙 손님이 청소를 원하면 객실 상세에서 [투숙 중 청소 요청]
- **할 수 없는 일:** 작업 배정, 판매 중단, 시작된 작업 취소. 시작 전인 투숙 중 청소는 취소할 수 있습니다.

#### **하우스키핑** HK-01 · HK-02

- **보이는 메뉴:** 객실 · 작업 (내게 배정된 작업만 보입니다)
- **하루 흐름:**
  1. 작업 화면에서 내 작업 확인
  2. 객실에 들어가며 [시작]
  3. 린넨이 없거나 방해 금지 등으로 막히면 [차단 등록] (풀릴 때까지 몇 분인지 적어 주세요)
  4. 풀리면 [해제]
  5. 끝나면 [완료]. 그러면 검사 작업이 자동으로 생깁니다.
- **참고:** HK-03은 근무가 끝난 직원입니다. 배정하면 '근무 시간이 아니다'라는 안내가 나오는 예시입니다.

#### **검사** IN-01

- **보이는 메뉴:** 객실 · 작업 (내게 배정된 검사만 보입니다)
- **하루 흐름:**
  1. 작업 화면에서 내 검사 확인
  2. [시작]
  3. [검사 결과 입력]에서 욕실·침구·바닥·비품을 확인하고 통과 또는 실패 선택
  4. 통과하면 객실이 `준비 완료`가 됩니다. 실패하면 사유를 적고, 재청소 작업이 자동으로 생깁니다.
- **할 수 없는 일:** 청소 작업 처리, 다른 사람의 검사 결과 입력.

> 화면에 버튼이 안 보인다면 그 역할로는 할 수 없는 일입니다. 버튼을 숨기는 것은 편의일 뿐이고, 최종 권한은 서버가 다시 확인합니다.

## 상태별

_화면의 상태 표시가 무슨 뜻이고, 그다음 무엇을 하면 되는지._

<a id="room-states"></a>

### 객실 업무 단계

객실 화면과 예약 화면에 보이는 단계입니다. 단계마다 다음에 할 일과 담당 역할이 정해져 있습니다.

| 단계 | 뜻 | 다음에 할 일 | 담당 |
|---|---|---|---|
| `청소 필요` | 손님이 나갔고 아직 청소 전 | 청소 작업을 배정하고 시작. 작업이 없으면(취소된 경우) 객실 상세에서 [재청소 작업 만들기] | **운영 관리자** → **하우스키핑** |
| `청소 중` | 청소하는 중 | 청소를 끝내고 [완료]. 막히면 [차단 등록] | **하우스키핑** |
| `검사 대기` | 청소는 끝났고 검사 전 | 검사를 배정하고 시작. 검사 작업이 없으면 [재검사 작업 만들기] | **운영 관리자** → **검사** |
| `검사 중` | 검사하는 중 | [검사 결과 입력] | **검사** |
| `준비 완료` | 검사 통과, 손님을 받을 수 있음 | 손님이 오면 [체크인]. 판매 중단 상태라면 먼저 [판매 재개] | **프런트** **운영 관리자** |
| `투숙 중` | 손님이 머무는 중 | 청소 요청이 있으면 [투숙 중 청소 요청], 퇴실하면 [체크아웃] | **프런트** **운영 관리자** |
| `투숙 중 청소` | 머무는 손님의 방을 청소하는 중 | 청소를 끝내고 [완료]. 이 동안에는 체크아웃할 수 없습니다 | **하우스키핑** |

- `판매 중단`은 업무 단계와 별개입니다. 새 손님의 체크인만 막고, 이미 머무는 손님이나 진행 중인 작업에는 영향이 없습니다.
- 한 객실에는 진행 중인 작업이 하나만 있을 수 있습니다.
- 작업을 만들거나 배정만 해서는 객실 단계가 바뀌지 않습니다. 담당자가 [시작]을 눌러야 바뀝니다.

<a id="task-states"></a>

### 작업 상태

| 상태 | 뜻 | 누를 수 있는 버튼 |
|---|---|---|
| `대기` | 담당자가 아직 없음 | **운영 관리자** [배정] [차단 등록] [작업 취소] · **프런트** 투숙 중 청소만 [작업 취소] |
| `배정됨` | 담당자가 정해졌고 시작 전 | 담당자 [시작] [차단 등록] · **운영 관리자** [재배정] [배정 해제] [작업 취소] |
| `진행 중` | 작업하는 중 | **하우스키핑** [완료] · **검사** [검사 결과 입력] · 담당자·**운영 관리자** [차단 등록] · **운영 관리자** [작업 취소] (사유 필수) |
| `차단됨` | 차단 사유 때문에 멈춤 | 차단 사유 옆 [해제] (담당자·관리자). 모두 풀리면 멈추기 전 상태로 돌아갑니다 |
| `완료` `취소` | 끝난 작업 | 없음. 작업 화면 위쪽 상태 버튼에서 '완료'·'취소'를 켜면 볼 수 있습니다 |

- [재개]: 시작했다가 멈춘 작업을 다시 시작할 때 [시작] 대신 보입니다. 처음 시작한 시각은 그대로 남습니다.
- '담당자 없음 · 진행 중단' 표시: 시작했던 작업이 담당자 없이 대기로 돌아간 경우입니다. 관리자가 다시 배정해야 합니다.
- 작업을 취소하면: 시작 전이었다면 객실 단계는 그대로이고, 시작한 뒤였다면 이전 단계로 돌아갑니다(청소·검사 → `청소 필요`, 투숙 중 청소 → `투숙 중`).

<a id="readiness"></a>

### 준비 예측

도착 예정 손님이 있는 객실마다, 남은 일(퇴실 대기 → 청소 → 검사)이 끝나는 시각을 계산해 '준비 마감'(체크인 30분 전)과 비교합니다. 이미 일한 시간과 차단이 풀릴 예상 시각도 반영합니다.

| 표시 | 뜻 | 할 일 |
|---|---|---|
| `늦을 예정` | 이대로면 준비 마감보다 늦게 끝납니다 ('N분 늦음') | 원인을 보고 배정을 서두르거나 차단을 먼저 해결하세요 |
| `예측 불가` | 예측에 필요한 정보가 없어 계산하지 않았습니다 | 이유를 확인하세요. 예: 풀릴 시각을 모르는 차단, 퇴실 예정이 지났는데 아직 투숙 중, 담당자 없이 멈춘 작업 |
| `빠듯함` | 마감 전에 끝나지만 여유가 30분이 안 됩니다 ('N분 여유') | 늦어지지 않도록 지켜보세요 |
| `여유 있음` | 마감보다 30분 이상 일찍 끝납니다 | 따로 할 일은 없습니다 |
| `준비 완료` | 이미 검사를 통과했습니다 | 판매 중단 상태라면 체크인할 수 없으니 확인하세요 |

- 정보가 부족하면 짐작해서 '여유 있음'으로 보여 주지 않고 `예측 불가`로 표시합니다.
- 근무표와 검사 실패 가능성은 예측에 넣지 않습니다(검사는 통과한다고 봅니다).
- 여유 30분과 작업별 예상 시간(체크아웃 청소 45분, 재청소 30분, 검사 10분, 투숙 중 청소 25분)은 데모용으로 정한 값입니다.

## 메뉴별

_화면마다 무엇을 볼 수 있고 어떻게 쓰는지._

<a id="menu-dashboard"></a>

### 대시보드

볼 수 있는 역할: **운영 관리자** **프런트**

- 맨 위 '준비 예측'에서 도착 예정 객실을 표시별로 셉니다. 그 아래는 확인이 필요한 객실 목록으로, 몇 분 늦을지와 원인을 함께 보여 줍니다.
- 가운데는 객실 단계별 수, 오늘 도착·출발, 상태별 작업 수, 직원별 업무량입니다. 작업 수를 누르면 그 상태만 걸러진 작업 화면으로 갑니다.
- 맨 아래 '도착 예정 객실 전체 · 예측 근거'를 펼치면 객실마다 어떤 일이 몇 분씩 걸리는지 볼 수 있습니다.

<a id="menu-rooms"></a>

### 객실 · 객실 상세

볼 수 있는 역할: **운영 관리자** **프런트** **하우스키핑** **검사**

- 객실 번호를 누르면 상세 화면이 열립니다. 업무 단계·판매 상태, 진행 중인 작업, 준비 예측 근거, 누가 언제 무엇을 했는지(이벤트 기록)를 볼 수 있습니다.
- [투숙 중 청소 요청] — **운영 관리자** **프런트**, 손님이 머물고 진행 중인 작업이 없을 때
- [재청소 작업 만들기] — **운영 관리자**, `청소 필요`인데 작업이 없을 때 (사유 입력)
- [재검사 작업 만들기] — **운영 관리자**, `검사 대기`인데 작업이 없을 때 (사유 입력)
- [판매 중단] · [판매 재개] — **운영 관리자** (사유 입력)

<a id="menu-tasks"></a>

### 작업

볼 수 있는 역할: **운영 관리자** **프런트** **하우스키핑** **검사** (하우스키핑·검사는 자기 작업만)

- 처음에는 `대기` `배정됨` `진행 중` `차단됨` 작업만 보입니다. 위쪽 상태·작업 종류 버튼으로 걸러 볼 수 있고, 걸러 둔 조건은 주소에 남아 그대로 공유할 수 있습니다.
- 작업 카드에는 객실 번호(누르면 객실 상세), 작업 종류, 상태, 예정 시각, 예상 시간('(기본값)'은 설정값), 담당자, 시작 시각, 생긴 이유, 차단 사유가 보입니다.
- [배정]: 청소는 하우스키핑, 검사는 검사 직원만 고를 수 있습니다. 목록에 직원별 현재 배정 건수와 근무 경고가 함께 보입니다.
- [차단 등록]: 사유(방해 금지·린넨 부족·비품 부족·시설 점검·인력 부재·기타)를 고르고 풀릴 때까지 몇 분인지 적습니다. 비워 두면 준비 예측이 `예측 불가`가 됩니다. '기타'는 설명을 적어야 합니다.
- [검사 결과 입력]: 욕실·침구·바닥·비품을 확인하고 통과 또는 실패를 고릅니다. 실패하면 사유를 적어야 합니다.

<a id="menu-reservations"></a>

### 예약

볼 수 있는 역할: **운영 관리자** **프런트**

- 왼쪽 '도착 예정'에서 [체크인], 오른쪽 '투숙 중'에서 [체크아웃]을 합니다. 예약마다 객실의 지금 단계가 함께 보입니다.
- 체크인은 객실이 `준비 완료`이고 판매 중일 때만 됩니다. 아직 안 되는 객실은 버튼이 꺼져 있고, 무엇이 남았는지와 객실로 가는 링크가 나옵니다. 예정보다 일찍 와도 객실이 준비됐다면 체크인할 수 있습니다.
- 체크아웃하면 청소 작업이 자동으로 생깁니다. 아직 시작하지 않은 투숙 중 청소는 함께 취소됩니다.
- 투숙 중 청소가 진행 중인 객실은 체크아웃이 막힌다는 안내가 미리 보입니다. 그래도 누르면 담당자와 해결 방법을 알려 줍니다.

<a id="menu-simulations"></a>

### 시뮬레이션

실행: **운영 관리자** · 보기: **프런트**

1. 데모 데이터셋 파일(JSON, 5MB 이하)을 올립니다. 저장소의 tools/simulator에서 `uv run stayops-simulator generate --seed 42 --out output/dataset-42.json`으로 만들 수 있습니다. 같은 파일은 한 번만 저장됩니다.
2. 데이터셋과 비교할 운영 방식을 고릅니다. 기준 방식(먼저 생긴 작업부터)은 항상 포함됩니다.
3. [실행]을 누르면 결과 표가 나옵니다. 방식마다 기준과 비교한 차이와 '개선'·'악화'가 글로 표시됩니다. 가동률처럼 높고 낮음만으로 좋고 나쁨을 말할 수 없는 지표는 판단하지 않습니다.
4. 이전에 실행한 결과는 '실행 기록'에서 다시 볼 수 있습니다.

> 시뮬레이션 결과는 데모 데이터로 운영 방식끼리 비교한 값입니다. 실제 운영 성과나 최적의 방법을 보장하지 않습니다.

## 문제 해결

_버튼이 꺼져 있거나 거절 안내가 나올 때 이유와 해결 방법._

<a id="help-cases"></a>

### 막혔을 때 해결 방법

#### 체크인 버튼이 꺼져 있어요 — '객실이 준비 완료가 되어야 체크인할 수 있습니다'

- **이유:** 정상입니다. 청소와 검사가 끝난 객실만 손님을 받습니다.
- **해결:** 안내에 적힌 남은 일을 진행하세요(빠른 시작의 흐름 참고). 데모에서는 101호가 처음부터 `준비 완료`입니다.

#### 체크인 버튼이 꺼져 있어요 — '판매 중단된 객실이라 체크인할 수 없습니다'

- **이유:** 판매 중단된 객실은 새 손님을 받지 않습니다.
- **해결:** **운영 관리자**가 객실 상세에서 [판매 재개] (사유 입력). 판매 재개는 판매 여부만 바꾸고, 객실을 준비 완료로 만들지는 않습니다.

#### 체크아웃이 안 돼요 — '시작된 투숙 중 청소가 있어 체크아웃할 수 없습니다'

- **이유:** 청소하는 중에 방을 비우면 작업 기록이 어긋나서 막습니다.
- **해결:** 담당 **하우스키핑**가 청소를 마치거나(차단이 있으면 먼저 해제), **운영 관리자**가 그 청소를 취소한 뒤 다시 체크아웃하세요.

#### 배정이 안 돼요 — '선택한 직원이 작업 예정 시각에 근무하지 않습니다'

- **이유:** 고른 직원이 그 시각에 근무하지 않습니다(예: HK-03).
- **해결:** 근무 중인 다른 직원을 고르세요.

#### 시작·완료가 안 돼요 — '해제되지 않은 차단 사유가 있습니다'

- **이유:** `차단됨` 작업은 시작하거나 완료할 수 없습니다.
- **해결:** 차단 사유 옆 [해제]를 누른 뒤 다시 시도하세요.

#### 작업을 만들 수 없어요 — '이 객실에 진행 중인 작업이 이미 있습니다'

- **이유:** 한 객실에는 진행 중인 작업이 하나만 있을 수 있습니다.
- **해결:** 안내에 있는 '진행 중인 작업 보기'를 눌러 기존 작업부터 처리하세요.

#### 청소를 취소했더니 객실이 `청소 필요`인데 작업이 없어요

- **이유:** 취소한 작업은 다시 살아나지 않습니다.
- **해결:** **운영 관리자**가 객실 상세에서 [재청소 작업 만들기] (사유 입력).

#### '다른 변경과 충돌했습니다'

- **이유:** 다른 사람이 같은 객실이나 작업을 먼저 바꿨습니다.
- **해결:** 화면이 최신 상태로 바뀌었으니 확인하고 다시 시도하세요.

#### '서버 응답을 받지 못했습니다'

- **이유:** 네트워크 문제로 처리됐는지 알 수 없습니다.
- **해결:** [같은 요청으로 다시 시도]를 누르세요. 같은 요청은 두 번 처리되지 않습니다.

#### '데이터 상태 확인이 필요합니다'

- **이유:** 저장된 상태끼리 서로 맞지 않습니다. 서버가 함부로 고치지 않고 멈춘 것입니다.
- **해결:** 화면의 추적 ID를 관리자에게 알려 주세요.

#### 버튼이 아예 안 보여요

- **이유:** 역할과 작업 상태에 따라 할 수 있는 버튼만 보입니다.
- **해결:** '역할별'·'상태별' 탭에서 누가 할 수 있는 일인지 확인하고 [사용자 변경]으로 역할을 바꾸세요.

> 모든 안내에는 '추적 ID'가 함께 나옵니다. 문제를 알릴 때 이 값을 같이 전달하면 서버 기록에서 해당 요청을 바로 찾을 수 있습니다.
