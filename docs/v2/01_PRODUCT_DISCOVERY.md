# StayOps — 문제 정의·리서치·가설 검증

> 상태: 공개 자료 기반 데스크 리서치 및 제품 가설  
> 기준일: 2026-11-04  
> 제약: 호텔 운영자 인터뷰와 내부 운영 데이터는 확보하지 못했다. 현장 문제 빈도·심각도·지불 의사·실제 성과는 입증되지 않았다.

## 1. 프로젝트 개요

- 프로젝트명: **StayOps — Room Readiness & Operations** (가칭)
- 도메인: 호텔·레지던스 객실 준비 및 하우스키핑 운영
- 지원 맥락: 핸디즈 / 어반스테이 소프트웨어 엔지니어 포지션
- 구현: Claude Code
- 제품·리서치·설계: ChatGPT와 사용자 협업
- 제품 형태: 객실·예약·청소·검사·작업자 정보를 연결해 준비 위험을 설명하고 운영 대안을 비교하는 운영 도구

### 현재 제품 가설

객실·예약·청소 작업·작업자 정보를 연결하고, 객실 준비 위험의 원인을 설명하며, 운영 조건 변경 시 결과를 시뮬레이션할 수 있다면 객실 준비 관련 의사결정을 더 빠르고 일관되게 수행할 수 있을 것이다.

이는 검증 전 `HYPOTHESIS`다. 실제 현장에서의 문제 크기나 기존 도구 대비 개선 효과를 입증한 사실로 표현하지 않는다.

## 2. 사업 맥락

핸디즈의 공개 사업 소개에는 숙박 자산 위탁 운영·관리(Plott Stay), 가격 운영, OTA 채널 운영 자동화, 다국어 고객 서비스, 자산 생애주기 관리(Plott AMC) 등이 소개되어 있다.

**해석:** 숙박 운영은 예약 화면만이 아니라 객실·시설·고객 응대·가격·정산 등 여러 업무와 데이터가 연결되는 영역이다.

**주의:** 공개 사업 소개는 내부 시스템의 상세 아키텍처나 현재 운영상의 문제를 보여주지 않는다. 내부 도구의 기능이나 부족한 점을 추정하지 않는다.

출처: https://handys.co.kr/business

## 3. 문제 후보와 선택 범위

### 탐색한 문제 후보

1. 객실 준비 지연을 늦게 인지할 수 있다.
2. 지연 원인이 청소·검사·린넨·비품·시설 이슈 중 무엇인지 빠르게 파악하기 어려울 수 있다.
3. 작업 우선순위가 체크인 예정 시각, 작업 소요 시간, 차단 사유, 작업자 가용성을 함께 반영하지 못할 수 있다.
4. 작업자별 업무량과 남은 근무시간을 고려한 배정이 어려울 수 있다.
5. 운영 조건 변경의 결과를 사전에 비교하기 어려울 수 있다.

위 항목은 현장 사실이 아니라 문제 탐색 후보(`HYPOTHESIS`)다.

### 선택한 문제 범위

**객실 준비 위험의 원인 설명 + 작업 우선순위 지원 + 운영 조건 변경 시 시뮬레이션**

단순 객실 상태판이나 작업 배정만으로 차별성을 주장하지 않는다. 공개 문서상 Oracle OPERA Cloud, Mews, Flexkeeping 등은 객실 상태 및 하우스키핑 관련 기능을 제공한다. 따라서 StayOps의 차별화 가설은 위험 계산에 사용한 입력과 원인을 설명하고, 대안별 운영 결과를 비교하는 데 둔다.

경쟁 제품이 유사 기능을 전혀 제공하지 않는다고 주장하지 않는다. 공개 문서에서 확인한 범위와 확인하지 못한 범위를 구분한다.

## 4. 공개 리서치

### 4.1 객실 청소 시간의 변동 요인

**Hotel room cleaning: Time study and analysis of influential variables in a Spanish hotel**

- 스페인 4성급 호텔에서 객실 청소 시간을 측정하고 영향 변수를 분석한 연구다.
- 작업 관련 변수가 총 청소 시간에 통계적으로 유의한 영향을 미쳤다고 보고한다.
- 일부 작업이 전체 청소 시간에서 큰 비중을 차지했다고 보고한다.
- 제품 설계에서 객실/작업 유형별 소요 시간을 하나의 고정 상수로 취급하지 않는 참고 근거로 활용한다.

**한계:** 특정 호텔의 연구 결과를 모든 호텔의 평균 또는 어반스테이의 실측값으로 일반화하지 않는다.

출처: https://www.jiem.org/index.php/jiem/article/view/3441

### 4.2 린넨 대기와 객실·고객 유형

**Employee Productivity of Hotel Room Attendants: An Input–Output Perspective**

- 홍콩 호텔의 객실 22개 청소 과정과 객실 정비 담당자 18명을 조사한 연구다.
- 린넨 공급 대기 시간이 생산성을 저해할 수 있음을 다룬다.
- 고객 세그먼트 및 객실 유형에 따라 청소 소요 시간이 달라질 수 있음을 다룬다.
- LINEN_SHORTAGE 차단 유형 및 작업별 예상 시간 모델의 참고 근거로 사용한다.

**한계:** 조사 표본과 환경이 제한적이므로 수치를 본 프로젝트 기본값으로 직접 가져오지 않는다.

출처: https://doi.org/10.1080/15256480.2021.1881941

### 4.3 작업자 스케줄과 객실 준비

**Capacity Planning for Resource Turnaround Operations**

- 대형 도심 호텔의 실제 데이터를 기반으로 하우스키핑 인력 배치를 연구한 논문이다.
- 작업자 교대 시작 시각을 분산하는 전략이 객실 준비 문제 및 고객 대기에 미치는 영향을 분석한다.
- 근무 시간과 작업량을 함께 고려하는 시뮬레이션의 참고 근거로 사용한다.

**한계:** 논문의 환경·가정·실험 결과를 StayOps의 성과 수치로 인용하지 않는다.

출처: https://doi.org/10.1287/msom.2025.0395

## 5. 가설과 검증 계획

### H1 — 준비 위험을 조기에 식별할 수 있는가?

- 가설: 체크인 시각, 남은 청소 시간, 검사 시간, 차단 상태를 연결하면 준비 지연 가능성을 사전에 분류할 수 있다.
- 검증: 합성 시나리오에서 계산 결과와 시뮬레이션의 실제 완료 시각 비교
- 지표: 위험 분류별 지연률, 위험 감지 리드타임, UNKNOWN 비율
- 한계: 합성 데이터에서의 성능은 실제 호텔 예측 정확도를 증명하지 않는다.

### H2 — 위험 사유 설명이 원인 파악에 도움이 되는가?

- 가설: 단순 위험 배지보다 계산 입력·작업·차단·검사 상태를 함께 보여주는 편이 원인 파악에 유리하다.
- 검증: 요약 화면과 원인 상세 화면의 과업 수행 비교
- 지표: 원인 식별 성공률, 과업 완료 시간, 오해 횟수
- 상태: 실제 호텔 운영자 검증은 미실시

### H3 — 대안 비교가 운영 판단을 지원하는가?

- 가설: 작업자 재배정, 우선순위 변경, blocker 해제 예상 시각 변경 등의 대안을 비교하면 상대적 결과를 이해할 수 있다.
- 검증: 동일 초기 데이터·seed에서 정책만 변경
- 지표: 정시 준비율, 평균 지연, 미완료 작업, 작업자 부하/초과 근무
- 한계: 입력 분포가 합성 가정이므로 현장 최적해를 의미하지 않는다.

### H4 — 이벤트 이력으로 사후 원인을 재구성할 수 있는가?

- 가설: 예약·작업·배정·차단·검사 상태 변경을 기록하면 객실별 타임라인을 재구성할 수 있다.
- 검증: 이벤트 및 현재 도메인 데이터를 이용한 타임라인 재구성 테스트
- 지표: 누락 이벤트, 중복 이벤트, 재구성 일관성

## 6. 인터뷰 제약과 대체 검증

운영자 인터뷰는 수행하기 어렵다는 제약을 전제로 한다. 인터뷰를 진행해야만 프로젝트가 성립하는 구조로 만들지 않는다.

대체 검증:
1. 공개 학술 연구 및 공식 제품 문서 조사
2. 업무 프로세스와 상태 전이의 논리적 일관성 검토
3. 합성 데이터 및 고정 seed 시나리오
4. 정상·예외·경계 조건 자동화 테스트
5. 계산 결과와 시뮬레이션 결과의 일관성 검증
6. 가능할 경우 비전문가 대상 화면 이해도 점검 — 단, 호텔 운영자 검증으로 표현하지 않음

## 9. 프로젝트 내부 평가 지표

이 지표는 포트폴리오 프로젝트의 동작·시뮬레이션 지표이지 사업 성과 KPI가 아니다.

- 정시 준비율 = 준비 대상 중 준비 마감 이전 READY 객실 비율
- 평균 지연 = 지연 객실의 준비 마감 대비 실제 READY 지연 시간 평균
- 위험 감지 리드타임 = 위험 최초 감지 시각과 준비 마감 사이 시간
- UNKNOWN 비율 = 필수 입력 부족으로 판정 불가한 객실 비율
- 작업 완료율 = 완료된 유효 작업 / 유효 작업
- 작업자 부하 = 근무 가능 시간 대비 배정 작업 예상 시간
- 시나리오 차이 = 기준 정책 대비 대안 정책의 지표 변화

모든 지표는 기간·분모·산식·누락 데이터 처리 방식을 함께 표시한다.
