### 제품 가설(현재)

객실·예약·청소 작업·작업자 정보를 연결하고, 객실 준비 위험의 원인을 설명하며, 운영 조건 변경 시 결과를 시뮬레이션할 수 있다면 객실 준비 관련 의사결정을 더 빠르고 일관되게 수행할 수 있을 것이다.

이 문장은 검증 전 가설이다. 실제 현장에서 이 문제가 얼마나 자주 발생하는지, 기존 시스템이 이를 얼마나 잘 해결하는지, 이 도구가 운영 성과를 얼마나 개선하는지는 아직 검증되지 않았다.

## 3. 문제 영역 탐색

### 3.1 초기 문제 후보

1. 객실 준비 지연을 늦게 인지한다.
2. 지연의 원인이 청소·검수·린넨·비품·시설 이슈 중 무엇인지 한눈에 파악하기 어렵다.
3. 작업 우선순위가 체크인 예정 시각, 작업 소요 시간, 차단 사유, 작업자 가용성을 함께 반영하지 못할 수 있다.
4. 작업자별 업무량과 남은 근무시간을 고려한 배정이 어려울 수 있다.
5. 운영 조건을 바꾸었을 때 객실 준비 결과가 어떻게 달라질지 사전에 비교하기 어렵다.

위 항목은 제품 탐색을 위한 문제 후보이며, 현장 사실로 확정된 내용이 아니다.

### 3.2 선택한 문제 범위

**객실 준비 위험의 원인 설명 + 작업 우선순위 지원 + 운영 조건 변경 시 시뮬레이션**

단순 객실 상태판이나 청소 작업 배정만 구현하면 기존 PMS·하우스키핑 제품과 기능 중복이 크다. 따라서 객실 준비가 늦어질 가능성을 설명하고, 그 근거가 되는 작업·차단·시간 정보를 연결하며, 운영 대안을 비교하는 쪽으로 범위를 좁힌다.

## 4. 공개 리서치 및 근거

### 4.1 객실 청소 시간은 단일 고정값으로 보기 어렵다

**Hotel room cleaning: Time study and analysis of influential variables in a Spanish hotel**

- 4성급 호텔에서 스톱워치 기반으로 청소 시간을 측정하고 영향 변수를 분석한 연구.
- 작업 관련 변수가 총 청소 시간에 통계적으로 유의한 영향을 미쳤다고 보고한다.
- 다섯 가지 작업이 전체 청소 시간의 2/3 이상을 차지했다고 보고한다.
- 제품 설계 시 객실 유형이나 작업 종류에 따라 소요 시간이 달라질 수 있다는 점을 고려할 근거로 사용한다.
- 특정 호텔의 관찰 결과를 모든 호텔의 평균으로 일반화하지 않는다.

출처: https://www.jiem.org/index.php/jiem/article/view/3441

### 4.2 린넨 공급 대기와 객실·고객 유형이 생산성에 영향을 줄 수 있다

**Employee Productivity of Hotel Room Attendants: An Input–Output Perspective**

- 홍콩 호텔의 객실 22개 청소 과정을 관찰하고 18명의 객실 정비 담당자를 조사한 연구.
- 린넨 공급 대기 시간이 생산성을 저해할 수 있다고 설명한다.
- 고객 세그먼트 및 객실 유형에 따라 청소 소요 시간이 달라질 수 있음을 다룬다.
- 제품의 차단 사유에 LINEN_SHORTAGE를 두고, 작업 시간을 단일 숫자로 고정하지 않는 설계의 참고 근거로 활용한다.

출처: https://doi.org/10.1080/15256480.2021.1881941

### 4.3 작업자 근무 시작 시각과 작업 배치가 객실 준비에 영향을 줄 수 있다

**Capacity Planning for Resource Turnaround Operations**

- 대형 도심 호텔의 실제 데이터를 기반으로 하우스키핑 인력 배치를 연구한 논문.
- 작업자 교대 시작 시각을 분산하는 전략이 객실 준비 문제 및 고객 대기를 줄일 수 있다고 보고한다.
- 근무 시간과 작업량을 함께 고려하는 시뮬레이션의 참고 근거로 활용한다.
- 논문의 실험 조건과 결과를 본 프로젝트의 성과 수치처럼 사용하지 않는다.

출처: https://doi.org/10.1287/msom.2025.0395

### 4.4 기존 PMS·운영 제품은 이미 객실 상태 및 하우스키핑 기능을 제공한다

**Oracle OPERA Cloud**
- 예약, 객실, 요금, 청구, 하우스키핑, 고객 정보 등을 다룬다.
- 객실 상태, 하우스키핑 배정, 유지보수 요청, 도착·출발 관리 기능을 소개한다.
- 출처: https://www.oracle.com/hospitality/hotel-property-management/

**Mews Operations**
- 예약·프런트데스크, 객실 상태, Dirty/Clean/Inspected 상태, 기본 작업 관리 등을 문서화한다.
- 출처: https://help.mews.com/s/article/Mews-Operations

**Flexkeeping**
- 객실 상태, 고객 정보, 대기 중 배정, 체크리스트, 작업 완료 등의 운영 화면을 소개한다.
- 참고 문서: https://help.mews.com/s/article/mobile-room-overview

**제품 전략상의 결론**
- 객실 상태판, 청소 작업 생성·배정만을 핵심 차별점으로 주장하지 않는다.
- 본 프로젝트의 차별화 가설은 객실 준비 위험을 계산하는 데 사용한 입력값과 원인을 투명하게 보여주고, 대안별 운영 결과를 비교하는 것이다.
- 경쟁 제품이 이러한 기능을 전혀 제공하지 않는다고 주장하지 않는다. 공개 문서에서 확인한 범위와 확인하지 못한 범위를 구분한다.

## 5. 가설과 검증 계획

### H1. 객실 준비 위험을 조기에 식별할 수 있다
- 가설: 체크인 예정 시각, 청소 예상 소요 시간, 검사 시간, 차단 사유를 연결하면 준비 지연 위험이 있는 객실을 사전에 식별할 수 있다.
- 검증 방법: 시뮬레이션 데이터에서 계산 결과와 실제 시뮬레이션 완료 시각을 비교한다.
- 지표: 위험 분류별 지연 비율, 위험 감지 리드타임, UNKNOWN 비율.
- 한계: 합성 데이터 기반 결과는 실제 호텔에서의 예측 정확도를 증명하지 않는다.

### H2. 위험 사유를 설명하면 운영자가 대응 대상을 이해하기 쉽다
- 가설: 단순 위험 배지보다 계산에 사용한 작업·차단·검사 정보를 함께 보여주는 편이 원인 파악에 유리하다.
- 검증 방법: 동일 시나리오를 요약 정보만 제공하는 화면과 원인 상세 화면으로 비교하는 사용성 점검을 수행한다.
- 지표: 원인 식별 성공률, 과업 완료 시간, 오해/잘못된 대응 횟수.
- 현재 상태: 제품 내 설명 가능성을 구현할 계획이며, 실제 사용자 검증은 미실시.

### H3. 운영 대안 비교가 작업 배치 판단을 지원한다
- 가설: 작업자 재배정, 작업 우선순위 변경, 차단 해제 예상 시간 변경 등을 시뮬레이션하면 대안별 객실 준비 결과를 비교할 수 있다.
- 검증 방법: 동일한 초기 데이터·seed에서 정책만 변경해 결과를 비교한다.
- 지표: 정시 준비 객실 비율, 평균 지연 시간, 작업자 유휴/초과 근무, 미완료 작업 수.
- 한계: 초기 작업 시간·인력 데이터는 합성 가정이다.

### H4. 작업 이력과 이벤트를 남기면 사후 분석이 가능하다
- 가설: 상태 변경과 차단·배정·검사 이력을 이벤트로 남기면 지연 원인을 재구성할 수 있다.
- 검증 방법: 이벤트 로그만으로 객실별 작업 타임라인을 재구성하는 테스트를 수행한다.
- 지표: 누락 이벤트 수, 타임라인 재구성 성공률, 중복 명령 처리 안정성.

## 6. 인터뷰 제약 및 대체 검증 전략

사용자는 호텔 운영자 인터뷰를 진행하기 어렵다고 명시했다. 따라서 인터뷰를 프로젝트 진행의 선행 조건으로 두지 않는다.

대체 방법:
1. 호텔 운영 관련 공개 학술 연구를 조사한다.
2. PMS 및 하우스키핑 솔루션의 공식 제품 문서를 비교한다.
3. 공개 자료에서 확인한 운영 개념을 바탕으로 프로세스와 도메인 모델을 설계한다.
4. 합성 데이터를 생성하되 모든 분포와 시간값을 `ASSUMPTION`으로 표시한다.
5. 경계 조건·예외 흐름·상태 전이 테스트로 도메인 모델의 일관성을 검증한다.
6. 시나리오별 시뮬레이션으로 정책 간 상대 비교를 수행한다.
7. 사용성 검증이 가능한 경우 동료 등 비전문가에게 화면 이해도 테스트를 수행하되, 이를 호텔 운영자 검증으로 포장하지 않는다.

## 9. 성공 지표(프로젝트 내부 검증용)

이 지표는 실제 사업 성과 KPI가 아니라 제품 동작 및 시뮬레이션을 평가하는 프로젝트 지표다.

- 객실 준비 정시율 = 체크인 deadline 이전 READY가 된 객실 / 준비 대상 객실
- 평균 준비 지연 분 = 지연 객실의 실제 READY 시각 - 위험 deadline
- 위험 감지 리드타임 = 위험 최초 감지 시각과 위험 deadline 사이의 시간
- UNKNOWN 비율 = 필수 입력 누락으로 위험을 판단하지 못한 객실 / 준비 대상 객실
- 작업 완료율 = 완료 작업 / 유효 작업
- 작업자 부하 = 근무 가능 시간 대비 배정 작업 예상 시간
- 시나리오 개선량 = 기준 정책 대비 대안 정책의 KPI 차이

지표를 표시할 때 분모·계산 기준·기간을 명시한다.
